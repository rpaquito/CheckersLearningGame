# App Icon (Phase 10a: Visual Assets — App Icon) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Task 1 is controller-executed, not delegated to an implementer subagent — see its own note.**

**Goal:** Replace the PWA phase's placeholder gold-checkers-king icon with real Draw Things-generated art matching the design spec's locked concept — "crowned checkers disc (king piece) as sensei", the same aura/headband/beard "sensei" treatment as Chess Sensei's own approved ivory-pawn icon, adapted onto a disc silhouette.

**Architecture:** This is a narrow, deliberate first slice of design spec §13 phase 10 ("New visual assets + native iOS + branding") — not the whole phase. Phase 10's remaining assets (the 3 background-theme images, 4 home-menu tile illustrations, 3 game-end mascot images) and the native iOS Capacitor setup are each their own separate, later plan, mirroring how Chess Sensei's own build actually shipped this work (`docs/superpowers/plans/2026-08-23-board-background-themes.md` and `2026-08-28-native-ios-app-capacitor.md` in the sibling repo are two of several separate plans, not one). The app icon comes first because it's the most-referenced asset (PWA manifest, browser tab, and — later — the native iOS app icon) and already has a placeholder explicitly built to be swapped at these exact paths with no other code change.

The generation pipeline is a direct, confirmed-working port of Chess Sensei's own icon-production task: Draw Things' local HTTP API (`POST http://127.0.0.1:7860/sdapi/v1/txt2img`, model `z_image_turbo`, already confirmed reachable), a full-bleed 1024×1024 production render, `sips` for the plain resized outputs, and a Python/Pillow safe-zone composite for the maskable variant (content confined to the centered 80%-diameter circle so no OS icon mask crops the headband/beard). The concept, prompt shape, and pipeline are copied from the sibling project's own approved, shipped icon — only the piece description changes (pawn → checkers king disc), per design spec §8's own explicit adaptation table.

**Tech Stack:** Draw Things.app (local, HTTP API Server enabled — already confirmed running), `curl`, `python3` + Pillow (confirmed installed), `sips` (macOS built-in). No npm dependency, no code beyond a doc-comment update and a CLAUDE.md entry.

**Spec:** `docs/superpowers/specs/2026-08-31-checkers-sensei-design.md` (§8's asset table — "App icon" row specifically — and its Generation pipeline paragraph).

## Global Constraints

- **Process (CLAUDE.md, hard repo rule):** no worktrees, no feature branches. Every task's changes are committed directly to `main` and pushed (`git push origin main`) immediately once verified — never batch multiple tasks into one unpushed commit. `CLAUDE.md` is updated at the end of this phase (Task 2).
- **Concept, locked by design spec §8 already — do not re-brainstorm it:** "a wise ivory checkers king piece character (a round disc with a crown symbol on top) with a golden headband tied in a knot with flowing ribbon tails, a wispy pale beard, calm closed eyes, a soft glowing cyan aura" on the app's own `#1A0B33` ink background. This mirrors Chess Sensei's own approved pawn-mascot concept exactly, per spec §8's adaptation table — the creative decision is already made; this plan executes it.
- **Full-bleed composition is mandatory.** Chess Sensei's own first production render had rounded corners baked into the image itself (a "card" look) that had to be re-prompted away — the prompt below already includes the same "no rounded corners, no border, no frame, no vignette, full-bleed... filling the entire frame corner to corner" language that fixed it there. If a render still shows a card look, do not proceed with it (see Task 1 Step 3).
- **Maskable safe zone is mandatory, not optional.** The generated art's headband/beard/crown must all stay inside a centered circle covering 80% of the 512×512 canvas's diameter — content outside that circle can be cropped by real OS icon masks. Task 1 Step 6 verifies this visually with a red-circle overlay before accepting the result, exactly as Chess Sensei's own plan did.
- **Task 1 is controller-executed, not delegated to an implementer subagent.** It's a sequence of slow (minutes per call), interactive, judged-by-eye Draw Things API calls — there's no code diff for a task reviewer to check, only images to judge. If running under `subagent-driven-development`, the controller performs Task 1 itself and skips the task-reviewer dispatch for it, exactly matching Chess Sensei's own plan's explicit precedent for this same kind of task.
- **The final accepted 1024×1024 render is committed, not left in `/tmp`.** Unlike Chess Sensei's plan (which produced iOS assets in the same task, same session), this project splits app-icon generation from the native iOS phase — a future plan needs the full-resolution source to populate the iOS asset catalog without re-generating art. Task 1 commits it as `public/icons/icon-master.png`.
- **Cost if any ruling above is wrong:** low. The concept can be re-generated later if it doesn't land well in practice (no other code depends on its specific appearance); the committed master render is purely additive convenience for a future plan.

- [ ] **Step 1: Confirm Draw Things is reachable**

```bash
curl -s -m 5 http://127.0.0.1:7860/ -o /dev/null -w "%{http_code}\n"
```

Expected: `200`. If not, open the Draw Things app and enable Settings → Advanced → HTTP API Server, then retry.

- [ ] **Step 2: Generate the full-bleed production render (2 candidates)**

```bash
curl -s -m 480 -X POST http://127.0.0.1:7860/sdapi/v1/txt2img \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "anime style digital painting app icon, a wise ivory checkers king piece character, a round disc with a small crown symbol on top, with a golden headband tied in a knot with flowing ribbon tails, a wispy pale beard, calm closed eyes, a soft glowing cyan aura radiating behind it, centered composition, full-bleed square composition filling the entire frame corner to corner with a solid deep dark indigo purple background, no rounded corners, no border, no frame, no vignette, bold clean flat shapes, high contrast silhouette, stylized poster illustration, no text, no watermark, no signature, no letters",
    "negative_prompt": "photorealistic, photo, camera, 3d render, realistic, muted colors, sepia, text, watermark, signature, blurry, low quality, western comic style, cluttered background, multiple characters, human face, realistic anatomy, rounded corners, border, frame, vignette, card, sticker, chess pawn, chess piece",
    "width": 1024,
    "height": 1024,
    "steps": 8,
    "sampler_name": "UniPC Trailing",
    "batch_size": 2
  }' -o /tmp/icon_production_response.json
```

Budget 2-3 minutes per request.

- [ ] **Step 3: Decode, inspect, and select a candidate**

```bash
python3 -c "
import json, base64
with open('/tmp/icon_production_response.json') as f:
    data = json.load(f)
for i, b64 in enumerate(data['images']):
    with open(f'/tmp/icon_production_{i}.png', 'wb') as out:
        out.write(base64.b64decode(b64))
    print(f'saved /tmp/icon_production_{i}.png')
"
```

Read both candidate PNGs with the Read tool. Pick the one that best matches the locked concept (a crowned checkers-disc "sensei" figure, gold headband, wispy beard, cyan aura, ink background) **and** genuinely fills the square edge-to-edge with no baked-in rounding/border/vignette.

If neither candidate qualifies — a rounded "card" look, a chess pawn instead of a checkers disc, a cluttered/off-concept result — adjust the prompt's emphasis (push harder on "full-bleed"/"no rounded corners", or on "checkers disc, not a pawn, not a chess piece") and regenerate via Step 2. Do not proceed with a candidate that still has a rounded-card look — every derived size below inherits that flaw.

Once a candidate is accepted, copy it to a stable working name:

```bash
cp /tmp/icon_production_0.png /tmp/icon_final.png   # adjust index to whichever candidate was chosen
```

- [ ] **Step 4: Commit the master render and produce the plain web icon sizes**

```bash
mkdir -p public/icons
sips -z 1024 1024 /tmp/icon_final.png --out public/icons/icon-master.png
sips -z 192 192 /tmp/icon_final.png --out public/icons/icon-192.png
sips -z 512 512 /tmp/icon_final.png --out public/icons/icon-512.png
sips -z 180 180 /tmp/icon_final.png --out public/icons/apple-touch-icon.png
sips -z 32 32 /tmp/icon_final.png --out app/icon.png
```

- [ ] **Step 5: Produce the maskable icon with a proper safe zone**

Content must stay inside a centered circle covering 80% of the 512×512 canvas's diameter, so an OS's own circular/rounded/squircle mask never crops the headband, beard, or crown.

```bash
python3 -c "
from PIL import Image

BG = (26, 11, 51)  # #1A0B33, the app's 'ink' token
CANVAS = 512
SAFE_DIAMETER = int(CANVAS * 0.8)  # 80% diameter = 40% radius safe zone

src = Image.open('/tmp/icon_final.png').convert('RGBA')
src = src.resize((SAFE_DIAMETER, SAFE_DIAMETER), Image.LANCZOS)

canvas = Image.new('RGBA', (CANVAS, CANVAS), BG + (255,))
offset = ((CANVAS - SAFE_DIAMETER) // 2, (CANVAS - SAFE_DIAMETER) // 2)
canvas.paste(src, offset, src)
canvas.convert('RGB').save('public/icons/icon-512-maskable.png')
print('saved public/icons/icon-512-maskable.png')
"
```

- [ ] **Step 6: Visually verify the maskable icon against a circular mask**

```bash
python3 -c "
from PIL import Image, ImageDraw

img = Image.open('public/icons/icon-512-maskable.png').convert('RGBA')
overlay = Image.new('RGBA', img.size, (0, 0, 0, 0))
draw = ImageDraw.Draw(overlay)
draw.ellipse([0, 0, img.width, img.height], outline=(255, 0, 0, 255), width=6)
preview = Image.alpha_composite(img, overlay)
preview.save('/tmp/maskable_circle_preview.png')
"
```

Read `/tmp/maskable_circle_preview.png` — confirm the headband, beard, and crown all stay inside the red circle. If anything crosses it, lower `SAFE_DIAMETER`'s `0.8` factor in Step 5 (more padding) and regenerate.
